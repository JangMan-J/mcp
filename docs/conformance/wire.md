### Amended

- `WIRE-META-4` no longer treats `clientInfo` as a required key. The spec table marks only `protocolVersion` and `clientCapabilities` required.
- `WIRE-TO-2` is only the hard maximum (`SHOULD`). Idle reset on progress is `WIRE-TO-3` (`MAY`, default off).
- `STDIO-STDERR-1` is the `MAY` capture. `STDIO-STDERR-2` is the `SHOULD NOT` treat-stderr-as-error rule.
- `VER-NOFALLBACK-1` and the HTTP legacy-body rows do not claim the spec forbids `initialize`. The compatibility matrix's dual-era client falls back. This client stays modern-only under PLAN.md N7.
- `VER-CACHE-1` caches in memory. The spec `MAY` persist is not taken. That is not a spec `MUST NOT`.
- `HTTP-ERR-7` is `SHOULD`, from SEP-2243, not `MUST`.
- `HTTP-RETRY-1` is the read re-issue with a new id from changelog major change 9. Writes are `HTTP-AMBIG-1` under PLAN.md N14, which narrows that `MUST` for non-read-only methods.
- `HTTP-PARAM-1` rejects an `x-mcp-header` reached through `$ref` instead of dereferencing it. The schema-extension heading says the chain must not pass through `$ref`.
- `EDGE-18` checks absent and negative `ttlMs` only. It does not floor strings or floats. The caching section has no such rule, and tag `schema.json` types `ttlMs` as integer.
- `TEL-SPAN-1` does not use the span name `mcp.client <method>`. The fetched semconv says the span name should be the method, optionally with a low-cardinality target.
- Parenthetical disposition qualifiers moved into the condition column. Combined strengths were split so each row has one strength and one check.
