# Operations conformance

Wave 0 operations lane. One row, one observable. Anchors are wiki-relative paths under `~/vaults/JangsWiki/Wiki/mcp` plus the heading text. Pins: wiki `docs@de3550c9fea3` (fetched 2026-11-16) and tag `2026-07-28` = `5f5440bb26a62e2cf3440b92da5a667efa03b267` (`git ls-remote` shows that SHA and no `^{}` peel). Compared normalized MUST/SHOULD/MAY sentences of the operations pages at that tag with the wiki. `schema/2026-07-28/schema.json` was read at the tag; the wiki has no `schema.json`. No MCP implementation was used.

Raised for the director, not decided here:

- Q38 (D9 / ELIC-FORM-2). `client/elicitation.md` Requested Schema excludes nested objects, arrays of objects, `$ref`, and other advanced features. Error Handling says servers MUST handle decline, cancel, or the client failing to process the request. It does not say which one the client sends. Plan default D9 is fail the round with `protocol-violation` and do not send `decline`. That default is not encoded.
- Q31 (D5 / CACHE-AUTH-1). The authorization lane uses this same id for D5. Private cache MUST NOT cross authorization contexts. The spec's example is a different access token. It does not say whether refreshing that token under the same grant is a new context. Plan default (grant id, public sharing off) is not encoded.
